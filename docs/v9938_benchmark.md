# V9938/MSX2 VRAM Benchmark

This benchmark measures the existing MSX VDP/VRAM implementation without
replacing the V9938 core or changing normal emulator behavior.

## Enable it

Use the dedicated PlatformIO environment:

```powershell
platformio run -e m5stack-stamps3-max-spiffs-msx2-official-embedded-bench
```

That environment adds:

```ini
-DENABLE_V9938_BENCH
-DV9938_BENCH_FRAMES=800
-DV9938_BENCH_SERIAL_OUTPUT=1
-DV9938_BENCH_VERBOSE=1
```

The normal environment does not define `ENABLE_V9938_BENCH`, so benchmark
hooks compile to no-op macros.

## Modes

Passive mode is the default. The emulator runs normally and the benchmark
observes real VRAM reads, VRAM writes, and VDP commands generated by the
software being emulated.

Synthetic trace mode is only a disabled skeleton for now. It should stay
disabled unless a future implementation can run controlled VDP operations
without disturbing the active emulator state.

## Output

Output is printed on the serial console with `std::printf`.

When `V9938_BENCH_VERBOSE=1`, progress is printed every 60 frames:

```text
[V9938Bench] frame=300 fps=58.9 read=1.42MB/s write=0.31MB/s cmd=HMMM:12 LMMM:2 HMMC:4 LMMC:1 LINE:3 FILL:8
```

At `V9938_BENCH_FRAMES`, default 800 in the benchmark environment, the benchmark prints:

- the original compact summary lines;
- a human-readable `[V9938Bench][REPORT]` block for manual comparisons;
- a CSV-compatible row with this header:

```text
[V9938Bench][REPORT] begin
[V9938Bench][REPORT] test rom=Aleste.rom backend=msx-vdp mode=passive frames=800 wall_ms=42123
[V9938Bench][REPORT] speed fps=18.99 avg_frame_ms=51.240 p99_frame_ms=67.880 realtime_vs_60fps=31.7%
[V9938Bench][REPORT] vram total_MBps=0.880 read_MBps=0.866 write_MBps=0.014 total_bytes_per_frame=48576.1 reads_per_frame=47120.3 writes_per_frame=774.8
[V9938Bench][REPORT] commands total=2400 per_frame=3.00 bytes_per_command=159.3 dominant=HMMM dominant_pct=63.4%
[V9938Bench][REPORT] command_mix HMMM=1522(63.4%) LMMM=96(4.0%) HMMC=421(17.5%) LMMC=116(4.8%) LINE=226(9.4%) FILL=19(0.8%) OTHER=0(0.0%)
[V9938Bench][REPORT] compare_hint=same_rom_same_bios_same_video_settings_lower_avg_ms_and_p99_ms_are_better
[V9938Bench][REPORT] end
```

CSV header:

```text
backend,mode,rom_name,frames,wall_time_ms,fps,avg_frame_time_ms,p99_frame_time_ms,total_vram_reads,total_vram_writes,total_vram_read_bytes,total_vram_write_bytes,total_vdp_commands,command_bytes,vram_read_MBps,vram_write_MBps,total_vram_MBps
```

The benchmark then stops collecting data and the emulator keeps running.

## Hook Locations

The VDP hooks are in `src/msx/core/msx_vdp.cpp`:

- `msx_vdp_read_vram_fast()` records 1-byte VRAM reads.
- `msx_vdp_write_vram_msx1()` and `msx_vdp_write_vram_msx2()` record 1-byte VRAM writes.
- `msx_vdp_command_point()` records command-engine reads.
- `msx_vdp_command_pset()` records command-engine writes.
- `msx_vdp_command_advance_step()` records direct HMMV, HMMM, and YMMM accesses.
- `msx_vdp_command_continue()` records direct HMMC writes.
- `msx_vdp_command_execute()` records command starts and estimated command bytes.

Frame hooks are in `src/msx/core/msx_core.cpp`:

- `V9938_BENCH_FRAME_START(state->romName)` at the start of `msx_core_step_frame()`.
- `V9938_BENCH_FRAME_END()` before the core frame counter increments.

The benchmark module lives in `src/bench/`.

## Interpreting Results

The passive benchmark measures the actual workload produced by the running
software. Results vary with ROM, BIOS, video mode, frame rate, rendering path,
performance settings, and whether VDP commands are instant or time-sliced.

The read/write counters represent observed emulator memory accesses, not a
hardware-accurate external bus trace. Command byte counts are estimates based
on VDP command registers at command start.

For human comparisons, use the `[V9938Bench][REPORT]` block first:

- `speed`: overall emulator speed during the benchmark window. Higher `fps` is better; lower `avg_frame_ms` and `p99_frame_ms` are better.
- `realtime_vs_60fps`: quick reference against a 60 FPS target. `100%` means 60 FPS, `50%` means roughly 30 FPS.
- `vram`: observed VRAM pressure. If code changes improve rendering or command handling, compare MB/s together with frame time.
- `total_bytes_per_frame`, `reads_per_frame`, `writes_per_frame`: normalized values that are easier to compare than raw totals.
- `commands` and `command_mix`: which VDP commands dominated this ROM/workload.

Compare only runs made with the same ROM, BIOS, video settings, benchmark frame
count, and performance mode. Different games or scenes can legitimately produce
very different VRAM and command profiles.
